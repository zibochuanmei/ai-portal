# 日志与调试说明

## 本地运行

在 `backend` 目录启动 FastAPI 后，日志会同时出现在 PyCharm 运行窗口和项目根目录的 `ai-portal/logs/backend/ai-portal.jsonl`。下面的查看命令从 `ai-portal` 项目根目录执行。文件采用 JSON Lines 格式，一行对应一条事件，便于按 `trace_id`、接口路径或状态码搜索。

首次启用 PostgreSQL 持久化时，按以下顺序执行：

```powershell
docker compose --env-file infra/.env -f infra/docker-compose.yml up -d postgres redis minio etcd milvus
cd backend
@"
DATABASE_URL=postgresql+asyncpg://ai_portal:change-me@localhost:5432/ai_portal
"@ | Set-Content .env
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

`backend/.env` 被 `.gitignore` 忽略，只用于 Windows 本地后端连接 Docker 映射出来的 `localhost:5432`；Docker 内部后端仍使用 Compose 注入的 `postgres` 主机名。

```powershell
Get-Content .\logs\backend\ai-portal.jsonl -Wait
Select-String -Path .\logs\backend\ai-portal.jsonl -Pattern 'trace_id|agent_run|failed'
```

如果需要更详细的调试信息，在 `infra/.env` 中设置 `LOG_LEVEL=DEBUG`，重启后端即可。

## Docker 运行

```powershell
docker compose --env-file infra/.env -f infra/docker-compose.yml up -d
docker compose --env-file infra/.env -f infra/docker-compose.yml logs -f backend
```

后端文件日志在 `logs/backend/`，Nginx 文件日志在 `logs/nginx/`。Docker 标准输出仍然保留，便于使用 `docker compose logs` 临时排查。

## 根据请求 ID 排查

每个请求都会返回 `X-Request-ID`。前端或浏览器开发者工具中复制该值，再在日志中搜索：

```powershell
Select-String -Path .\logs\backend\ai-portal.jsonl -Pattern 'a-request-id'
```

正式接入认证、任务和 Agent 后，相关服务必须继续沿用同一个 `trace_id`，并记录用户、任务、Agent、模型别名和错误码。禁止记录访问令牌、模型密钥、密码、上传文件原文和敏感 Prompt。
