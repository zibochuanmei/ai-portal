# 技术选型与项目骨架对齐说明

## 当前结论

项目采用技术选型文档中的模块化单体路线：Vue 3 + TypeScript + Vite 负责 Portal，Python + FastAPI 负责后端，PostgreSQL 保存业务和权限事实，Redis/后续 Celery 承担异步任务，MinIO 保存文件，Milvus Standalone 承担向量检索。当前阶段只验证端到端演示链路，不把尚未验收的 Agent、RAG 和模型能力标记为已完成。

## 已对齐内容

| 技术选型要求 | 当前骨架落点 |
| --- | --- |
| Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus | `frontend/` |
| FastAPI、Pydantic、REST/OpenAPI | `backend/app/main.py`、`backend/app/api/` |
| 模块化单体 | `backend/app/` 下的领域包边界 |
| Docker Compose、Nginx | `infra/docker-compose.yml`、`infra/nginx/` |
| PostgreSQL、Redis、MinIO、Milvus、etcd | Compose 基础服务 |
| structlog、trace_id、日志落盘 | `backend/app/core/logging.py`、`backend/app/core/middleware.py` |

## 有意分阶段的内容

SQLAlchemy/Alembic、Celery Worker、企业 OIDC/Keycloak、LangGraph、Model Gateway、PaddleOCR、文档解析、Embedding、RAG 检索、Prometheus/Grafana 尚未在演示骨架中实现。它们会分别在数据库、异步任务、认证、Agent、RAG 和运维阶段按接口契约接入，避免先搭出无法运行的空服务。

## 日志约定

后端日志同时写入标准输出和 `logs/backend/ai-portal.jsonl`，按文件大小轮转。Nginx access/error 日志写入 `logs/nginx/`。请求入口生成或透传 `X-Request-ID`，后端响应会回写同名响应头；后续鉴权、任务、Agent 和模型服务应继续绑定 `user_id`、`task_id`、`agent_id`、`model_alias` 等字段。

日志中不得写入 Token、API Key、密码、文件原文或敏感 Prompt。生产部署时将 `logs/` 挂载到服务器数据盘，并配合容量告警和清理策略。
