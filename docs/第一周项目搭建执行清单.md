# 前期搭建执行清单

这份清单用于四人协作的前两个月。当前项目骨架已经上传 GitHub，接下来重点是把演示骨架升级为可持久化、可测试、可接入真实模型的开发底座，再开始具体 Agent 和工作流实现。

## 当前已完成

- GitHub `main` 已有可运行版本，前后端目录和基础文档已同步。
- Vue 3 + TypeScript + Vite 前端可以构建。
- FastAPI 后端提供健康检查、演示身份、工作流目录、运行和文件上传接口。
- 员工和平台管理员两种演示角色已建立，后端完成工作流权限边界。
- Docker Compose 已配置 PostgreSQL、Redis、MinIO、Milvus Standalone 和 etcd；没有 Docker 时可以先运行前后端演示。
- Python 版本要求已固定为 3.13.15，Node.js 版本要求已固定为 24.21.0。
- 日志、环境变量模板和基础测试文件已加入项目。

## 第一阶段剩余任务

1. 四台电脑完成 Python 3.13.15、Node.js 24.21.0、Git 和分支环境统一。
2. 所有人从 GitHub 拉取 `main`，确认前端构建和后端健康检查通过。
3. 创建并评审 PostgreSQL、SQLAlchemy、Alembic 的第一版表结构：用户、部门、角色、工作流、授权关系、会话、消息和运行记录。
4. 将当前内存中的演示用户、工作流和运行记录迁移到数据库，保留演示数据初始化脚本。
5. 将演示身份替换为 JWT，同时保留企业 SSO/OIDC 适配接口；没有企业认证前不开放自由注册。
6. 完善管理员接口：工作流目录、员工授权、部门归属、用户停用和审计日志。
7. 接入 MinIO 和异步任务，完成文件上传、解析任务、失败重试和状态查询。
8. 接入 Model Gateway，先适配智谱和通义千问，统一超时、重试、错误和调用日志。
9. 接入 Milvus，完成一个真实文档处理工作流的知识库检索和引用返回。
10. 选择一个制衣业务场景做端到端验收，再按同一接口规范扩展其他工作流。

## 暂不进入本阶段的任务

- Supervisor 和自动意图识别
- 本地意图模型和最终本地大模型选型
- 复杂多智能体自主规划
- 知识图谱和图数据库
- 微服务拆分和生产级高可用集群

这些能力保留在架构扩展点中，等单工作流链路、权限和数据底座稳定后再实施。

## 验收标准

- 环境：四台电脑能按 README 使用 Python 3.13.15 创建虚拟环境。
- Git：成员能从 `main` 拉取，从 `develop` 创建个人功能分支并提交。
- 前端：`npm run build --prefix frontend` 通过，页面可访问。
- 后端：`GET /health` 返回 `status=ok`，`python -m pytest -q` 在 Python 3.13.15 环境通过。
- 身份：员工和管理员返回不同角色信息，管理员入口受后端权限保护。
- 工作流：员工只能看到和运行已经授权的工作流，未授权调用返回统一错误。
- 文件：允许的文档和图片可以上传，非法扩展名和超限文件被拒绝。
- 数据：数据库迁移可以重复执行，初始化数据不会重复插入。
- 日志：请求带有 `trace_id`，敏感信息不写入日志，日志内容不提交 Git。
