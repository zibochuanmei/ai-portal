# 第一周项目搭建执行清单

这份清单用于四人协作的第一周，目标是让项目具备可运行、可提交、可继续开发的基础。

## 推荐顺序

1. 创建远程 Git 仓库，约定 main 和 develop 分支。
2. 在本地确认项目目录和提交规范，四人从 develop 创建各自功能分支。
3. 创建 Vue 3 + TypeScript + Vite 前端项目。
4. 创建 FastAPI 后端项目，先提供 /health。
5. 创建 Docker Compose，配置 PostgreSQL、Redis、MinIO、Milvus Standalone 和 etcd。
6. 创建 .env.example，所有连接地址、密码、模型密钥只从环境变量读取。
7. 运行 Compose 配置检查，确认基础服务可以启动。
8. 前端增加登录页、员工工作台和管理员入口的页面骨架。
9. 后端增加数据库连接、SQLAlchemy 模型、Alembic 迁移和初始化数据。
10. 建立两种第一阶段产品角色：employee 和 platform_admin。
11. 增加演示登录和当前用户接口；正式企业 SSO 在接口层预留适配器。
12. 实现 Agent 列表、Agent 授权和服务端权限校验。
13. 前后端联调，补充健康检查、登录、Agent 列表和越权访问测试。

## 和原清单相比的三个调整

- 数据库迁移放在登录和测试账号之前，否则账号没有可靠的数据结构。
- 登录页和后端当前用户接口一起完成，避免只有页面没有真实身份上下文。
- Agent 授权放在用户、角色、部门数据之后，并要求后端二次校验；前端只负责展示后端返回的可用 Agent。

## 每一步的验收结果

- Git：远程仓库存在 main、develop，团队成员能从 develop 创建分支。
- 前端：npm run build 成功，页面能打开。
- 后端：GET /health 返回 status=ok。
- 基础服务：docker compose config 通过，PostgreSQL、Redis、MinIO、Milvus、etcd 容器可查看状态。
- 数据库：迁移命令可重复执行，初始化数据不会重复插入。
- 身份：员工和管理员能得到不同角色信息。
- 权限：未授权 Agent 的列表不返回，直接调用接口也会被后端拒绝。
- 联调：员工登录后能看到自己的 Agent，并能创建一次演示运行。

## Git 初始化命令

远程仓库创建后，在项目根目录执行：

    git remote add origin <远程仓库地址>
    git branch -M main
    git push -u origin main
    git switch -c develop
    git push -u origin develop

当前工作区处于 detached HEAD，正式接入远程仓库时先按上面的命令建立团队分支。
