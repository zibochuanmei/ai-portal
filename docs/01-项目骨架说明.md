# AI Portal 第一阶段项目骨架说明

## 本阶段已完成

- Vue 3 + TypeScript + Vite 前端入口
- FastAPI 后端入口和 /health 健康检查
- 演示身份、Agent 列表和模拟 Agent 执行接口
- 前端聊天工作台、我的智能体、管理中心页面
- PostgreSQL、Redis、MinIO、Milvus Standalone、etcd 的 Compose 编排
- 前后端 Dockerfile
- 环境变量模板和基本测试样例

## 现在可以验证的链路

1. 前端加载 Agent 列表。
2. 员工选择已授权 Agent。
3. 员工输入问题。
4. 前端调用 /api/v1/agent-runs。
5. 后端返回模拟结果。

## 下一阶段开发顺序

1. 接入 PostgreSQL 和 SQLAlchemy，落地用户、部门、Agent、授权关系。
2. 实现 JWT 演示登录，并保留企业 SSO 对接适配层。
3. 把 Agent 列表从内存常量改为数据库查询。
4. 实现默认拒绝的 Agent 授权校验，前端只展示后端返回的可用 Agent。
5. 接入 MinIO 文件上传和异步解析任务。
6. 接入 Model Gateway，统一适配智谱、通义千问和后续本地模型。
7. 接入 Milvus，建设文档切分、Embedding、检索和引用链。
8. 再实现 Supervisor：只接收当前用户已授权的 AuthorizedAgentSet。

## 当前明确不做

- 不把复杂多 Agent 编排放在第一天。
- 不把权限判断放在前端。
- 不让业务 Agent 直接连接 Milvus。
- 不在代码中写入模型 API Key 或服务器密码。
- 不把最终本地模型型号提前写死。

## 与技术选型的落地状态

当前后端已经按模块化单体预留 `auth`、`org`、`permission`、`agent`、`controller`、`model_gateway`、`file`、`task`、`rag`、`vector_store`、`audit` 和 `worker` 边界；业务逻辑仍集中在演示接口中，后续按领域逐步迁移。

已落地的基础设施包括 Vue 3、FastAPI、PostgreSQL、Redis、MinIO、Milvus Standalone、etcd、Docker Compose、Nginx，以及 `structlog + trace_id` 日志链路。SQLAlchemy/Alembic、Celery、真实身份认证、Model Gateway 和 RAG 服务需要在下一阶段按接口契约接入。
